# N11 (proven quality) and N9 (fair hardware): short plan

Branch `claude/n11-n9`. The owner is a beginner on a Millenium MPS-150; both items make the scores fairer and stop
kit bugs from coming back. N11 has no screens; N9's screens get a mockup first (`docs/mockups/n9-kit-calibration.html`).

## N11 · Proven quality
1. **Real-kit MIDI fixtures** (`src/input/fixtures/*.json`): raw MIDI bytes with timestamps from a session, plus the
   chart, tempo, note map and the result it must give (notes landed, extras at most, accuracy at least).
   - Recording: `T.recordMidi()` / `T.saveFixture(name)` in the dev play-test driver (`scripts/playtest/helpers.js`)
     taps `receiveMidi` (a dev hook `onRawMidi` in `src/input/hits.ts`) and downloads nothing: it prints the JSON for
     the owner to save under `src/input/fixtures/`.
   - `src/input/fixtures.test.ts` replays every fixture through the real input path (bounce + crosstalk filters, note
     map) and the matcher, and checks the expectations. The first fixture is generated from the emulated MPS-150
     (retriggers + crosstalk on a ghost-note groove); the owner's real sessions are added during the M2 checklist.
2. **Automated play test** (`scripts/playtest/run.mjs`, `npm run playtest`): starts the API (temp `DATA_DIR`) and Vite
   on their own ports, launches the installed Google Chrome headless (no new dependency: the DevTools protocol over
   Node's built-in WebSocket), turns the coach off (no Claude usage), and plays lessons with the emulated kit as a
   **Beginner** and a **Solid** player. Checks per take: a verdict appears, never "…", no page errors, the tempo ladder
   moves the way the verdict says, the run is saved. `--quick` (stage 1 + one lesson per later stage, a few minutes)
   is for every merge; `--full` walks the whole path. Prints a report and exits non-zero on a failure.

## N9 · Fair hardware
1. **Per-pad velocity calibration**: "hit soft, then loud" per pad in the calibration wizard; each pad's range maps to
   a common scale (soft → 30, loud → 120) before scoring, so accents, ghosts and dynamics are judged the same on every
   pad. Stored with the note map (`velocity` per pad); default = no change.
2. **Per-pad retrigger profile**: the same step's loud strokes measure each pad's retriggers (gap and loudness); the
   bounce filter uses the pad's own window and ratio instead of one global 60 ms / 0.7.
3. **Sound check from the throne**: a "play along" check that plays click, band and coach voice in turn and asks
   "too quiet / OK / too loud" with pad answers (hi-hat / snare / floor), adjusting the sliders.
4. **Left-handed setup**: a setting that mirrors stickings in hints, intro slides and "How it moves" (R ↔ L).
Engine parts (velocity mapping, per-pad bounce, mirroring) are pure and tested; the wizard step, the sound-check flow
and the left-handed toggle wait for the mockup.
