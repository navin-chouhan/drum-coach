## Major

**M1 · journey · The Journey notices are cut to one line, so the weekly recap, the wrists question, the setup nudge,
the health line and the hearing tip can't be read.** Verified (traced; widths estimated).
`features/journey/JourneyScreen.tsx:78-80` puts every notice (the Monday recap, `SETUP_NUDGE`, `SORE_ASK`, or the coach
line plus the new badge / new stages / health line) into `TitleBar coach=…` (line 107). The title bar renders it as
`CoachLine singleLine` (`ui/TitleBar.tsx:16`), which is `numberOfLines={1}` with `adjustsFontSizeToFit` and
`minimumFontScale={0.8}` (`ui/CoachLine.tsx:39`). The width is 910 pt of content, minus the title box (~150), the
mascot and the right-hand buttons (~260 with "Check my kit ▶ / Not now" or "All good / A bit sore"). That leaves
~420 pt, or about 55 characters at 14.4 pt. `weekRecap` is ~150 characters (`packages/core/src/engine/progress.ts:229-236`),
the sore health line ~140 (`journey/model.ts`), `HEARING_TIP` 98, and the coach line plus one of them is longer still. Each
one ends in an ellipsis. The web shows them in a slim strip of their own (`src/lesson/TodayView.tsx`, D9 "one notice
at a time"). The health line's "If something hurts, stop" is the part that gets lost.
Repro: a profile with runs from last week, open Journey on a Monday: the recap reads "Last week you played 42 minutes. Your no…".
Fix: render the notice as its own strip, a `Banner` with up to 2 lines between the title bar and Up next, with its buttons on the right.
Keep the title bar's coach line to `v.coachLine`. Re-check the one-screen height budget (m7) when doing it.

**M2 · journey · Kit gestures stay live behind Journey's "⋯ More" sheet: the hi-hat pedal × 3 opens today's lesson
under the open sheet.** Verified (traced).
`JourneyScreen.tsx:101` `useKitMoves({ yes: start, next: other, listen: hear })` has no `enabled`. `MoreSheet`
(`journey/MoreSheet.tsx:20`) is a `ToolFrame`, an RN `Modal` over the same screen, so Journey stays focused and
`useIsFocused` stays true. A pedal × 3 or crash × 2 runs `start` → `router.push('/lesson/…')`, and the lesson opens
under the still-visible More sheet. Ride × 2 swaps the hero, and tom 2 × 2 opens "Hear it" the same way. Setup does
it right (`setup/SetupScreen.tsx` `useKitMoves(…, { enabled: tool === null })`), and so does the lesson
(`enabled: !more && …`).
Repro: Journey → ⋯ More → hi-hat pedal × 3.
Fix: `useKitMoves({ … }, { enabled: !more })` in JourneyScreen. Optionally let the sheet's own tiles answer the
"yes" gesture.

## Minor

**m1 · setup · Kit test plays a tapped drum twice when "Play drum sounds on the iPad" is on.** Verified.
`setup/SetupScreen.tsx:264` `onPadPress={pad => { getAppHitBus().emitPad(pad, 100); audio.playNow(…) }}`. The emit
isn't wrapped in `withoutKitSound` (the touch pads do this, `play/TouchPads.tsx:74`), so `startKitSounds`
(`play/kitSounds.ts:27-30`) plays the same drum again. Fix: `withoutKitSound(() => getAppHitBus().emitPad(pad, 100))`.

**m2 · journey · The show-off badge is never announced on Journey.** Verified.
`journey/model.ts:281` calls `earnedBadges(runs, s.lessons, checkpoints)` without the ready songs. The web passes them
(`src/lesson/TodayView.tsx:90-91`: `earnedBadges(…, undefined, ready)` with `songVerified && songReady`). G2 fixed the
same thing on Progress (QA2 m2), but not here. Fix: read `storage.songs.list()` in `useJourney` and pass the ready ids,
as Progress does.

**m3 · journey · The recap, "New badge" and "New stages" lines stay up for the whole app session.** Verified (traced).
`JourneyScreen.tsx:55-56` (`recap` state), `64-65` (`badges` state) and `74` (`newStages` state) are kept "for this
visit". On the web a visit ends when the tab changes, because `src/ui/App.tsx:127` unmounts `TodayView`. On the iPad,
Journey is a tab that stays mounted (`app/(main)/_layout.tsx` Tabs), so these lines stay in the coach line until the
app is killed, even into the next week. Fix: clear the three states on blur, e.g.
`useFocusEffect(useCallback(() => () => { setRecap(undefined); setBadges([]); }, []))`, and derive `newStages` per focus.

**m4 · coach voice · The "Coach voice volume" setting isn't applied to most speech.** Verified (traced).
`setVoiceVolume` runs only in the coach's `voiceOn` (`coach/coach.ts:58`, used by `speakOnce`) and in Setup's "Test the
voice" button (`setup/CoachVoicePanel.tsx:43`). The lesson's spoken verdicts and live tips (`lesson/useLesson.ts:62,78`),
Journey's Monday recap (`JourneyScreen.tsx:61`) and "How it moves" (`lesson/HowItMoves.tsx:10`) call
`sayNow`/`sayNext`, which use whatever `volume` was set last: 1 after launch. Also, Setup → Sound's "Test coach voice"
plays a DrumAudio word (`setup/SoundPanel.tsx` `say`: `prepareWords` + `playNow`), not the expo-speech voice the
coach really speaks with, so it tests the wrong voice. Fix: read `readSettings(kv).voiceVolume` inside `sayNext`
(`coach/voice.ts`) on every call. In SoundPanel, test the voice with `sayNow(VOICE_TEST)`.

**m5 · midi · The fallback auto-select drops a non-e-Drum kit's selection when it's unplugged.** Suspected (traced, not
run). `platform/midiCore.ts` `selectionIsGone` treats any explicitly selected source whose name isn't a preferred
name as gone when it goes offline, and `autoSelect` then clears the selection. Plug in a second kit (or Network MIDI)
picked in Dev → MIDI, unplug it and plug it back: it isn't reconnected. Only Setup's picker saves `drumcoach.midiInput`,
which `useKitConnection.restore` re-selects. The web keeps the saved input ("listens to the saved input when it's there",
`src/input/useMidi.ts`). Fix: when falling back, remember the dropped selection's name and re-select it when an input
with that name comes back online. Or save Dev → MIDI picks to `drumcoach.midiInput` as well.

**m6 · CLAUDE.md · Constant `innerHTML` in the technique art, and a header that says there is none.** Verified.
`play/dom/demoArt.ts:38-39` sets `svg.innerHTML = '<defs>…'` (gradients and filters) under a targeted
`eslint-disable-next-line no-restricted-syntax`. It's constant markup copied from the web (`src/ui/demoArt.ts:38`), so
there's no injection, but `play/dom/TechniqueDom.tsx:5` says "No HTML strings". Fix (optional, both apps): build the
`<defs>` with `createElementNS` (about 20 lines), or correct the header.

**m7 · journey · The one-screen budget is tight: about 808 of 834 pt before any optional line.** Suspected (sizes summed
