# Brief: I2, the app-wide keyboard fallback and kit consolidation
Read `SCREENS-COMMON.md` (the owner is away: follow the web app).

1. **Hardware keyboard → hit bus, app-wide** (CLAUDE.md: Space kick, S snare, A/Q hi-hat closed/open, Z pedal,
   E/R/F toms, W crash, T ride; same as `src/input/keyboard.ts`). React Native has no global key events, so build it
   properly: a tiny Expo module `apps/mobile/modules/drum-keys` (Swift: a key-command or `pressesBegan` hook on the
   root view controller, sending key down/up with a host-time timestamp on the same mach clock as drum-midi). Feed
   `getAppHitBus().emitPad(pad, velocity, time)`, plus Esc and Enter events for the screens. Mount it once in
   `app/_layout.tsx`. The Swift compiles in the cloud iOS build. Keep it small and mirror drum-midi's structure. No
   npm packages.
2. **Kit consolidation** (`apps/mobile/src/ui/**`): promote the duplicated local components into the kit with
   one API each: Group/GroupRow, Stepper, ToolFrame, PadMap (A7c); Notice, Bars, Track, Dots (A7d); Field,
   CheckRow, Choice, Tabs-with-disabled, Warn (A8); TempoLadder, StepPills, TimingLineView (A7b); the coach's speech
   bubble and offline cards (A7e). **Only add them to `src/ui`**, with tests where there's logic. Switch the
   imports in `features/{setup,firstRun,pads,latency,coach,journey,progress}` to the kit, and leave
   `features/{lesson,songs,practice}` (other agents are editing them; they switch afterwards).
3. **One source for drum colours**: `src/play/theme.ts` reads the approved colours from `src/ui/tokens.ts`, with the
   web theme kept as the alternative.
