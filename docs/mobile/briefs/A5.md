# Brief: A5, Data and home-server client (iPad)

## Goal
The iPad keeps its own data (D3: start fresh, no import, no sync) and talks to the home server (D2: server first; an
optional Anthropic API key is a later step). Implement `Storage` and `HomeServer` from
`apps/mobile/src/platform/contracts.ts` (read-only), plus the coach-context builder the server now accepts.

## Requirements
- KV store: synchronous (`expo-sqlite`'s key-value storage or a sync table), never throws, same keys as the web
  (`drumcoach.noteMap.<kit>`, `drumcoach.padCal.<kit>`, settings key) so core code ports unchanged.
- SQLite: tables and JSON shapes mirroring `server/db.ts` for runs (+ capped take hits), settings, plans, ai_lessons;
  migrations versioned; `PRAGMA journal_mode=WAL`.
- Token only in `expo-secure-store`; never logged, never in the KV store, never in error text.
- `HomeServer.call`: bearer header, no Origin header, timeouts, typed failures (401→unauthorized, 403→forbidden,
  429→rate-limited, network→unreachable). Plain http on the LAN is allowed by ATS `NSAllowsLocalNetworking`.
- Coach context builder: from local runs/settings/lesson progress → the `server/coachContext.ts` schema, trimmed to
  ≤ 50 KB (most recent first); a test proves the cap and that the output passes the server's zod schema (import the
  schema from `../../server/coachContext.ts` in the test only, or copy it with a parity test).
- Pure logic (mappers, context builder, failure mapping) is unit-tested with Vitest; storage/secure-store/fetch are
  injected so tests run in Node.
