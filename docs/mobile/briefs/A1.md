# Brief: A1, Core extraction (Phase 1)

## Goal
Create `@drum-coach/core` at `packages/core`: pure TypeScript with no DOM and no React Native, consumed as source.
It holds the engine, content, schemas and the MIDI input path, so the web app, the server and the Expo iPad app share
one teaching brain. **The web app's behaviour must not change**: T0 stays at 349 tests passing, the build stays
clean, lint stays at no new problems, and the playtest keeps passing.

## The rules
1. **Mechanical moves only.** Use `git mv` and leave a shim at the old path. No logic changes, except the injections
   below, and those keep the web behaviour identical.
2. **Shims and server imports use relative `.ts` paths**, e.g. `src/engine/scoring.ts` becomes
   `export * from '../../packages/core/src/engine/scoring.ts';`. Don't import via `@drum-coach/core` here: Node's
   type stripping refuses `.ts` files under `node_modules`, and the server runs as `node server/index.ts`. Keep
   `node --env-file-if-exists=.env server/index.ts` starting (start it, wait for the "listening" line, then stop it).
   New code in `apps/mobile` imports `@drum-coach/core/...`.
3. **Inside core, imports are relative with `.ts` extensions**, as today.
4. **Boundary lint rule** for `packages/core/src/**`: `no-restricted-globals` (`window`, `document`, `navigator`,
   `localStorage`, `sessionStorage`, `fetch`, `performance`, `AudioContext`, `requestAnimationFrame`) and
   `no-restricted-imports` (`react`, `react-dom`, `react-native`, `expo*`). `setTimeout` is allowed.
5. Core tests must pass **with `performance` undefined**: a core Vitest setup deletes `globalThis.performance`, in the
   node environment.
