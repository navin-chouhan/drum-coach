# Brief: A4p2, the take engine in core (`createTake` + `planEvents`, B21)

## Goal
One clock-agnostic take engine in `@drum-coach/core`, so the iPad and later the web score takes **identically**.
It covers count-in, the click plan, wait mode, endless takes, live checks, the end of a take and results. The iPad
uses it now; the web's `src/play/player.ts` moves onto it in a later, separate step (not in this brief).

## Read first
`CLAUDE.md`, `docs/mobile/AUDIO-DESIGN.md` §1.2, §2.1–2.3, §4–6 (the spec: `TakeDeps`, `Take`, `planEvents`, heard
times, 300 ms lead, tick ~10×/s, keep ≥ 2 s planned, stop reasons, interrupted takes keep whole bars),
`packages/core/src/play/audioPort.ts` (the contract; read-only), `packages/core/src/play/take.ts` (A1's superseded
draft: replace it), `src/play/player.ts` + `src/play/audio.ts` (the web engine to port: start / startExternal /
finish / position / waitGroups / liveCheck / count-in / band / voice), `packages/core/src/engine/{run,scoring,
lesson,liveCoach,meter}.ts`, `packages/core/src/input/hits.ts`, `docs/mobile/BOARD.md` D6 (keep a take if ≥ 2
whole bars when interrupted, flagged, not counted for the ladder or stars), `scripts/mobile-playtest/reference*`
(the web reference scores).

## Owns
`packages/core/src/play/**` except `audioPort.ts` (the orchestrator's; request changes in your report). New tests
next to them. **No changes to `src/` (web) and no changes to other core files**, except adding pure helpers that
`player.ts` keeps today and the take needs. Those are moved with `git mv`-style extraction plus a re-export from the
old location, so the web is unchanged; list them.

## Deliver
1. `planEvents(spec, fromBeat, toBeat): AudioEvent[]`: pure. Clicks (accents, subdivisions), count-in words or
   clicks, band notes as the web plans them. All times are **heard** Clock ms.
2. `createTake(deps, chart, opts): Take` per §2.3: `start()` picks zero = now + lead + count-in, prepares words and
   schedules 4 s; `tick(now)` keeps ≥ 2 s planned in native, runs live checks and the end; `position(now)`;
   `stop('user' | 'interrupted')`; `state`; `onFinish`. Hits come from `deps.onHit` (the core hit bus, already on
   the Clock). Matching and scoring use the existing core scoring, exactly as `player.ts` does: same windows, same
   results.
3. `createMetronome` for Practice (an endless spec, the same planner).
4. **Parity tests (critical):** replay both core fixtures through `createTake` with a fake AudioPort and fake clock,
   at times +0 and +1e9. They must produce the web reference results in `scripts/mobile-playtest/reference/*.json`
   (landed, extras, accuracy, mean, spread: the same values). Also synthetic streams: count-in, a wait-mode group
   advance, endless whole bars, an interrupted take at bar 3 that keeps bars 1–2, cancel on stop, and a late chunk
   dropped and counted.
5. Notes in your report: which parts of `player.ts` are now duplicated in core (for the later web migration), and
   any `AudioPort` change you need.
