# Brief: A0, Recon (read-only)

## Goal
Write `docs/mobile/RECON.md`, the map every later agent works from when building the Expo iPad/iPhone app. The app
reuses the engine, content and schemas as a shared `@drum-coach/core` package and rebuilds the screens natively. The
web app on Linux Chrome must keep working unchanged.

## Read first
`CLAUDE.md`, `docs/SPEC.md`, `docs/KIT.md`, `docs/LEARNING.md`, `docs/PLAN.md`, `docs/OVERNIGHT.md`,
`docs/TEST-REPORT-2026-10-26.md`, `docs/PLAYTEST.md`, `README.md`, `package.json`, `server/index.ts`, `server/db.ts`,
`server/ai/providers.ts`, `src/input/hits.ts`, `src/input/useMidi.ts`, `src/input/store.ts`, `src/play/audio.ts`,
`src/engine/scoring.ts`, `src/engine/run.ts`.

## Owns
`docs/mobile/RECON.md` only. **Change nothing else.** Don't commit; the orchestrator commits.

## RECON.md must contain (file:line everywhere)
1. **Browser API uses in candidate core folders** (`src/engine`, `src/content`, `src/coach/schemas.ts`,
   `src/youtube/schemas.ts`, `src/input/hits.ts`, `src/input/settings.ts`, and whatever they import transitively).
   Cover `window`, `document`, `navigator`, `localStorage`, `fetch`, `performance`, `AudioContext`/Web Audio,
   `requestAnimationFrame`, `setTimeout` (fine, but list it), DOM types, React imports, Vite-only features
   (`import.meta.env`, `?url`, `?raw`, `import.meta.glob`), and JSON or asset imports. For each, say whether it's a
   blocker for a pure-TS core and give the smallest fix (move it to the web app, inject it, or a platform interface).
2. **The core import graph.** Which files in the candidate core import from outside the core (`src/input/store.ts`,
   `src/ui`, `src/play` …)? For example, `src/input/hits.ts` imports `./store`, which uses `localStorage` and
   `fetch`. Propose the exact final core file list and the files that must stay web-only.
3. **Clock assumptions.** Every place that assumes `performance.now()` / `MIDIMessageEvent.timeStamp` /
   `AudioContext` time (e.g. `scoring.ts`, `run.ts`, `hits.ts`, `src/play/audio.ts`). Note what "one monotonic ms
   clock" must mean for the core API.
4. **Screen inventory.** Every screen/view component (`src/ui`, `src/lesson`, `src/play`, `src/coach/*View`,
   `src/youtube/*Mode`, `src/voice`, `src/notation`), with its line count, the README section it maps to, its
   main dependencies (Canvas, VexFlow, Web Audio, AudioWorklet, getUserMedia, getDisplayMedia, window.open), and a
   suggested v1 / later / web-only tag (default v1: Journey, lesson player, Practice, Progress, Setup with kit, pads,
   latency and server, and Songs with inline YouTube).
5. **localStorage and sessionStorage keys.** Key, file:line, value shape, and whether it is mirrored to the server.
6. **All `/api` calls.** Client file:line, method, path, and the server route (file:line) that serves it. Group them:
   persistence, AI coach, voice (TTS/STT), YouTube, other. Mark which a phone can't serve without the home server.
7. **Server dependencies that can't run on iOS** (claude CLI, Piper, Whisper/uv, better-sqlite3, stored files).
   List the SQLite tables and row shapes from `server/db.ts`, for the expo-sqlite mirror.
8. **Test inventory.** The test file count per folder, and which tests would move to core. Also what
   `scripts/playtest/` and `src/input/fixtures/` do, and how a Mac could replay the fixtures to an iPad over Network
   MIDI.
9. **Web-only features with no iOS equivalent** (tab capture, popup player, others you find), each with a one-line
   reason.
10. **Risks** for the core extraction (B17) and the screen rewrite, ranked, each with a mitigation.

## Done when
RECON.md exists with every section, the claims are checked against the code (grep, don't guess), and it is under
about 600 lines. Use tables. Finish with a 10-line "what A1 should do first" list.

## Do not touch
Any file except `docs/mobile/RECON.md`. Don't run the dev server; reading and grepping is enough. `npm test` is fine
if useful.
