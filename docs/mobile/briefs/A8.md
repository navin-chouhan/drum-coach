# Brief: A8, Songs (inline YouTube) and imports
Read `SCREENS-COMMON.md` first. Songs was "next phase" in D5. The owner has now asked for the complete app, so it's
built now, after the v1 screens in the merge order.

**Web source:** `src/youtube/{SongsPage,SongView,TempoMode,LearnMode,JamMode,PlayMode,GridEditor,yt,api,schemas}.ts(x)`,
`src/content/{charts,SongsView}.ts(x)`, `packages/core/src/engine/{tempo,youtube,youtubeSongs,stageSong,midiImport,
jam,band,onsets}.ts`, CLAUDE.md's **YouTube rules** (official IFrame player only; never download, rip, record or
store audio or video; search only through the server's Data API key). Mockups: none. Follow the web's Songs look
translated through A7a's kit (the web's layout, iPad landscape).

**Owns:** `apps/mobile/app/(main)/songs.tsx` (add Songs to the sidebar as the web has it: tell the orchestrator so
A7a's nav adds the entry), `apps/mobile/app/song/**`, `apps/mobile/src/features/songs/**`, `apps/mobile/src/youtube/**`.

**Builds:** the YouTube IFrame player in an **Expo DOM component** (as A6n did for VexFlow: `@expo/dom-webview` is
already installed; `playsinline`, start on a user tap, a clear error per video that blocks embedding), the song clock
with the web's smoothing (`yt.ts`) on the iPad Clock, the per-video beat grid (`tempo.ts`), Tempo / Learn / Jam /
Scored (Play) modes and Stage mode as the web, search via `HomeServer` (`/api/youtube/...`; unreachable state),
drumless uploads; **tab-capture features gated off with the reason** (B13: no YouTube audio capture on iOS),
MIDI/audio file import via `expo-document-picker` (you may add exactly that package at the version SDK 58.0.17 names
if ≥ 7 days old with no install scripts) as the web's "Import files". Songs are stored in Storage (the web's chart
and yt_song shapes; A5's schema has the tables or add a migration in `src/data` only through a request to the
orchestrator).
