# Brief: A4p3, backing audio (`BackingPort`) in drum-audio

## Goal
Implement `AudioPort.backing` (contract: `packages/core/src/play/audioPort.ts`, `BackingPort`: `load(uri)`,
`start({at, offsetMs, rate})` heard at Clock time `at`, `stop()`, `anchor()` read from the render clock), so imported
backing tracks (Songs, A8; the web's chart audio) and band audio play in sync with the click and MIDI on the one
host-time clock. Design: `docs/mobile/AUDIO-DESIGN.md` §1.4 and §6 (drift: the core corrects against `anchor()`).

## Owns
`apps/mobile/modules/drum-audio/**` and `apps/mobile/src/platform/audio.ts` (+ `audioCore.ts` and tests). A4 part 1
is merged; build on it, keeping its conventions (pure Swift core with SwiftPM tests in `ios/Core`, policies mirrored
in TS with Vitest tests).

## Requirements
- Swift: AVAudioFile for local file URIs (Documents, as A8 stores imports) → an AVAudioPlayerNode on the backing bus
  scheduled with `AVAudioTime(hostTime:)` from the heard time minus `heardOffsetMs`; offset by seeking the
  segment (`scheduleSegment`); `rate` with an AVAudioUnitTimePitch (pitch kept) between the node and the mixer.
  `anchor()` = (Clock ms now, file position heard now) from `playerTime(forNodeTime:)`. Stop and reschedule safely.
  Handle sample-rate conversion (the engine runs at 48 kHz) and route/config changes (re-anchor).
- Never stream or store YouTube audio (CLAUDE.md): this is only for local files the owner imported.
- TS: `backing` is non-null when the module is available; the levels bus `backing` exists already.
- Tests: the pure parts (heard→host conversion, the segment start frame from offsetMs and rate, anchor math) in TS
  and SwiftPM. The cloud iOS build (`.github/workflows/ios.yml`) compiles the Swift on PRs to main. Write it to
  compile first time.
- Debug: add a "Backing" card to `/dev/audio` (load a bundled 4-bar test tone generated at runtime, start it on the
  next bar with the click, show the drift from `anchor()` over 2 minutes).
