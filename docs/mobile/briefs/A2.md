# Brief: A2, Expo shell (Phase 1)

## Goal
Create `apps/mobile`, the Drum Coach iPad app shell: Expo, TypeScript, Expo Router, a development build. It builds
on the owner's Mac exactly the way the Gate 0 probe did, and loads `@drum-coach/core` from `packages/core`. No feature
screens yet: they wait for mockups (D4).

## Read first
`CLAUDE.md`, `docs/mobile/BOARD.md` (decisions D0–D5 and the dev loop), `docs/mobile/GATE0.md` §9 (what happened on
the real Mac and iPad, including the Expo version mismatch crash), `docs/mobile/GATE0-CHECKLIST.md` §A/A2 (the
owner's setup), `spikes/midi-probe/` (a working Expo SDK 58 app on the owner's iPad: copy its versions, app.json,
.gitignore and patterns), `apps/mobile/src/platform/contracts.ts` (read-only).

## Facts that decide the setup
- **iPad only, landscape locked** (D0): `ios.supportsTablet: true`, `ios.isTabletOnly: true`, orientation landscape.
  Layouts are width-based, so iPhone can be added later.
- **The owner's toolchain:** macOS 27.2, Xcode 27.1, Node 24, CocoaPods 1.17, free Apple ID (Personal Team), iPad on
  iPadOS 26.5. Bundle id `com.drumcoach.app`. Never set a team ID.
- **Expo versions:** use the newest SDK 58 patch, consistently. `expo` latest is 58.0.21 today, so verify it. Every
  `expo-*` package must be the version that SDK's `bundledNativeModules.json` names. Gate 0 crashed at launch
  because `expo` 58.0.19 allowed an `expo-file-system` whose prebuilt framework needed a newer
  `expo-modules-core`. After installing, check that no `expo-*` package is resolved to a version the installed
  `expo`'s `bundledNativeModules.json` doesn't allow (write a small check script, `scripts/check-expo-versions.mjs`,
  and run it).
- **React Native needs one exact React version.** RN's renderer rejects a different `react`. The web root uses
  `react@^19.3.1`, and Expo SDK 58 bundles `react@19.3.0`. **So `apps/mobile` is NOT a root workspace.** It's its
  own npm project (its own `package-lock.json`, like the spike). It depends on
  `"@drum-coach/core": "file:../../packages/core"` and resolves core's runtime deps (`zod`, `@tonejs/midi`, the same
  ranges as root) from its own `node_modules`. Metro: `watchFolders` includes `packages/core`;
  `resolver.nodeModulesPaths` includes `apps/mobile/node_modules`, so core's imports resolve without a root install.
  Package `exports` must work (`@drum-coach/core/engine/scoring` → `src/engine/scoring.ts`).
- **The dev loop is Mac build, Linux Metro.** `npx expo start --dev-client --lan` from Linux must serve the app to
  the iPad.

## Deliver
1. **The app:** `package.json` (scripts `start`, `ios`, `ios:device`, `prebuild`, `typecheck`, `test`, `doctor`,
   `check:versions`), `app.json`, `tsconfig.json` (strict, bundler resolution, path to core), `metro.config.js`,
   `babel.config.js` if needed, `.gitignore` (`node_modules`, `ios`, `android`, `.expo`), `vitest.config.ts`
   (node environment; includes `src/**/*.test.ts` and `modules/**/src/**/*.test.ts`, so A3's tests run here).
2. **app.json / Info.plist:**
   - name "Drum Coach", slug `drum-coach`, `com.drumcoach.app`, dev client;
   - iPad-only, landscape;
   - `NSLocalNetworkUsageDescription` (Metro + home server + Network MIDI), `NSBonjourServices`
     `["_apple-midi._udp"]`;
   - ATS `NSAllowsLocalNetworking: true` (an `http://` home server on the LAN, D2);
   - `NSMicrophoneUsageDescription` (voice coach, later);
   - placeholder icon and splash (simple, generated).
3. **Expo Router:** `app/_layout.tsx` (safe areas, keep-awake while the app is foreground, a light theme) and
   `app/index.tsx`, a placeholder home: app name, build info (versions, core reachable: show
   `DEFAULT_NOTE_MAP.snare` imported from `@drum-coach/core/engine/kit` to prove the core link), and a link to
   `/dev/midi` (A3 builds that screen; your link must not crash if the route isn't there yet).
4. **`src/platform/keepAwake.ts` and `src/platform/capabilities.ts`**, implementing `KeepAwake` and `Capabilities`
   from the contracts.
5. **`apps/mobile/README.md`:** the owner's setup and daily loop, short and true (Mac build/install, Linux Metro,
   reinstall every 7 days, signing pop-ups, the troubleshooting learned in Gate 0).

## Checks (paste outputs)
- `cd apps/mobile && npm ci && npx tsc --noEmit && npx vitest run` (one tiny test proving the core import resolves).
- `npm run check:versions` passes.
- `EXPO_OFFLINE=1 npx expo prebuild --platform ios --no-install --clean` succeeds. Check that the generated Info.plist
  has the keys above, that `UISupportedInterfaceOrientations~ipad` is landscape only, and that `UIDeviceFamily` is
  `[2]`. Then delete `ios/`.
- Metro bundle smoke test:
  `npx expo export --platform ios --dev --output-dir <scratch>` (or `expo export:embed`) bundles without resolution
  errors, which proves the core import works through Metro.
- From the repo root: `npm test`, `npm run build` and `npm run lint` give the same results as before (root lint must
  not lint `apps/mobile`. If it does, write the exact `eslint.config.js` ignore line in your report and the
  orchestrator adds it. Don't edit root files).
