## Major

**M1 · ui · The full-screen lesson player gets the root stack's header bar.**
`app/_layout.tsx:24` declares only `(main)` with `headerShown: false`. `app/lesson/_layout.tsx:5` makes `lesson` a
nested Stack, so the `<Stack.Screen options={{ headerShown: false }} />` in `app/lesson/[id].tsx:9` and
`app/lesson/chart.tsx:10` configures the *inner* stack only; the root stack shows its default header (title
"lesson", back button) above the player's own black bar. The other full-screen routes (`welcome/index`,
`practice/play`, `practice/metronome`, `song/[id]`) have no nested layout, so their `Stack.Screen` reaches the root and
they're fine. This breaks "full screen while playing" (mockup NOTES) and eats ~50 pt of the 834.
Fix: in `app/_layout.tsx` add `<Stack.Screen name="lesson" options={{ headerShown: false }} />` next to `(main)`
(or delete `app/lesson/_layout.tsx` and set `animation: 'fade'` per screen). Confirm with the `lesson-ready.png`
screenshot of `e2e/lesson-to-progress.yaml`.

**M2 · practice · Practice's play screen has no touch pads, so without the kit it can't be played.**
`features/practice/PlayScreen.tsx:170-230` draws the sheet and the side cards but no `TouchPads`/`KitView`; the lesson
player swaps them in when no kit is connected (`features/lesson/LessonScreen.tsx:204-210`, mockup touch-pads:
"It replaces the keyboard fallback"). I2's hardware keyboard (known) helps only with a keyboard attached.
Fix: under the sheet, when `!useKitConnected()` (from `features/lesson/useLesson.ts:29`), render
`<TouchPads emitPad={(p, v, t) => getAppHitBus().emitPad(p, v, t)} playNow={audio.available ? (s, g) => audio.playNow(s, g) : undefined} now={getMidiPort().clock.now} activeDrums={…myPads} testID="practice-touch-pads" />`
in a ~150 pt row (shrink the sheet's `minHeight`), as the lesson does.

**M3 · practice · Practice takes ignore interruptions (D6).**
Only the lesson listens (`features/lesson/useLesson.ts:103-104`: `audio.onInterruption` and `AppState`). Practice's
engine (`features/practice/engine.ts:29-55`) and `PlayScreen.tsx` have neither, so a call, Siri, the Home button or
a lock mid-take leaves the take running with JS timers frozen; on return it ends with the away bars scored as missed,
is saved as a normal run (`takeRecord.ts:31-41` only copies `f.interrupted`, which nothing sets) and counts for Climb
(`PlayScreen.tsx:74-82`). D6: keep if ≥ 2 whole bars, flagged, not counted.
Fix: in `practiceEngine.start` subscribe `audio.onInterruption(e => { if (e.type === 'began' || e.type === 'engine-stopped') take.stop('interrupted'); })`
and `AppState.addEventListener('change', s => { if (s !== 'active') take.stop('interrupted'); })`, removing both in
`onEnd`; in `PlayScreen`'s `onSaved` skip Climb when `take.interrupted`, and make `climbAfterTake` ignore runs with
`summary.interrupted`.

**M4 · progress · "Practise" on a song row does nothing.**
`features/progress/ProgressScreen.tsx:22-26` handles `lesson` and `practice` only; `progress.ts:153` returns
`{ kind: 'song' }` for `yt-…`/`jam-yt-…` runs (Songs saves those: `songs/songTake.ts:93`, `songs/modes.ts:141`), so the
button in "Your lessons" (line 166) is dead. The comment on line 25 ("songs come after v1") is out of date: Songs
merged. The web opens the song (`src/ui/ProgressView.tsx:243`).
Fix: `else router.push(songHref(t.songId) as never);` with `songHref` from `features/songs/songsModel.ts:89` (song ids
are `yt-<videoId>`, `data/songs.ts:62`, the same string), and drop the comment.

## Minor

**m1 · ui · Every hit makes two to four native calls and two JSON parses.** `ui/hooks.ts:37-38` calls `kitName()`
(`hooks.ts:16-19`: `port.selection()`, and `port.listInputs()` when there's no selected name, both synchronous
native calls) and `JSON.parse` for the note map and the pad calibration on each hit. Scoring uses host time, so
it's latency for the kit view and the bridge budget (B24), not accuracy. Fix: cache `kitName()` and refresh it in
`port.onInputsChanged`; cache the parsed map and calibration and drop the cache from `subscribeKitStore`
(`features/pads/kitStore.ts:19`) and on `kv.set` of those keys.

**m2 · lesson · Wrong path in the More sheet.** `features/lesson/LessonScreen.tsx:228` says "⚙ Setup → Your kit →
Latency" (the web's tabs); the iPad's Setup has a "Latency" group with **Measure** (`setup/SetupScreen.tsx:96-99`).
Fix: "Run the latency test first (Setup → Latency → Measure)".

**m3 · setup · Keychain read on every render.** `features/setup/SetupScreen.tsx:191` is a `useEffect` with no
dependency list, so `hasApiKey(keychain)` runs after every Setup render (each hit re-renders Setup through
`useLastHit`). Fix: `[]` as on line 204, and re-read once when the API-key tool closes (pass a `version` from
`SetupScreen`'s `close`).

**m4 · setup · `useLatencyRouteSync()` is mounted twice on Setup.** `SetupScreen.tsx:42` duplicates
`app/(main)/_layout.tsx:40` (Setup is inside `(main)`): two `writeSettings` per route change, two settings
notifications. Fix: delete line 42 (keep `FirstRunScreen.tsx:27`: `/welcome` is outside `(main)`).

**m5 · songs · Song takes ignore interruptions too.** Nothing in `features/songs/**` listens to
`audio.onInterruption` or `AppState` (only the lesson does). YouTube pauses in the background, so the clock stops,
but the take isn't ended or flagged. Fix: as M3, in `songTake.ts`'s owner screens (`JamPanel`, `PlayPanel`,
`LearnPanel`): stop with `'interrupted'` on those events.

**m6 · ui · The not-found screen still uses the A2 theme.** `app/+not-found.tsx:3,24-28` uses `src/theme` colours and
a plain `Link` ("Back to the home screen"), unlike every other screen. Fix: `Screen` + `TitleBar` + `Button` from
`src/ui`, label "Back to Journey", `router.replace('/')`.

**m7 · journey · Three builders for the lesson route.** `features/journey/JourneyScreen.tsx:18`,
`features/lesson/route.ts:43` and `features/coach/coach.ts:26` each build `/lesson/<id>?item&mode`. They agree today;
the next param added to one will not reach the others. Fix: keep `lesson/route.ts` `lessonHref`, import it in Journey,
Progress (`PathView.tsx:7`, `ProgressScreen.tsx:12`, `SkillMapView.tsx:8`) and the coach.

**m8 · coach · Two chart stores.** The coach's exercises live in the key-value store (`features/coach/charts.ts:10`,
written by `coach.ts:62` and `CoachPanel.tsx:241`); imports live in the `charts` table (`ImportCard.tsx:44`). The
storage's context source reads the table's `source = 'ai'` rows (`data/store.ts:63-65`), which nothing writes, and
`/lesson/chart` looks up LIBRARY + the key-value store only (`features/lesson/drill.ts:10`), so a plan item or drill
naming an imported chart says "This drill no longer exists". Fix: save coach exercises to `storage.charts` with source
`'ai'` (the web's `POST /api/charts`), read Practice, drills and the context from that one table, and migrate the kv
list once.

**m9 · native · The app can't export a fixture replay for `compare.mjs`.** M8/T4 compares what the iPad heard with the
web reference, but the app's "Copy debug info" (`src/dev/midiSession.ts:97`) has `hits` as a *count* and a 40-entry
log (`LOG_SIZE`, line 47), and `scripts/mobile-playtest/compare.mjs:40-47` accepts only the probe's JSON or
`{ hits: [...] }`. The ghost-groove fixture has 136 hits. Fix: keep every hit since **Reset** (cap 5000) and add
`replay: { timeBase: 'host', hits: [{ time, pad, note, velocity }] }` to the report; let `compare.mjs` read
`kind: 'drum-coach-midi-debug'` from `replay`. Until then the final checklist uses the probe app for M8.
